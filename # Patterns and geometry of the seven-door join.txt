# Patterns and geometry of the seven-door join


Anchor first. Everything else is surround.


A single local Chrome History sequence visited seven exact Google Docs object IDs. Each visit is a `docs.google.com/document/d/<ID>/edit` row in the preserved Windows Default profile. Each later empty Drive revision is the same ID. Order matches. Gaps from visit to empty revision are 3.005–7.770 s. The seven empties occupy 245.622 s (19:50:23.052–19:54:28.674 EDT, 7 Sep 2026). That is the receipt. It is not a controller.


Do not mix clocks. 7 Sep 19:50 is the object sequence. 25 Sep 23:41 is AppX/Codex activation on the same machine family. 26 Sep 00:30–01:14 is live tree + CUA config. Those are three registers. Joins across them are labeled. They are not the same event.

Revision arithmetic is not uniform. Six pairs are **n → n+1**. Door 7 is **8 → 18**. That is a different quotient: either intermediate revisions exist and were not the “empty” marker, or the empty landing is not the immediate successor. Five other empty Docs with empty priors are **negative controls**. They show “empty now” is not automatically “was emptied in this sequence.”

## 2. Time geometry (two clocks inside one sequence)


**Visit→empty Δ** (the join width):


```
3.387  3.700  7.254  4.234  3.902  7.770  3.005
```


Two modes, not a smooth smear:


- **Short:** 3.005, 3.387, 3.700, 3.902, 4.234 — five doors, ~3–4.2 s  
- **Long:** 7.254, 7.770 — doors 3 and 6  


Mean ≈ 4.750 s, median 3.902 s. The median sits in the short mode. The two longs are the outliers, not the center.


That pattern is compatible with “open → wait for Docs to bind → clear → next,” with occasional extra wait (load, conflict, tab). It is also compatible with a person. **Δ alone does not pick a controller.** It bounds the mechanism: whatever wrote the empty revision was already in a session that could commit within a few seconds of a local Chrome navigation to that exact ID.


**Visit→visit spacing** (the walk, not the edit):


| step | gap |
|---|---|
| 1→2 | 29.634 s |
| 2→3 | 17.626 s |
| 3→4 | 41.263 s |
| 4→5 | 50.345 s |
| 5→6 | 52.338 s |
| 6→7 | 54.798 s |


After door 3 the walk **lengthens and stabilizes near 50–55 s**. The edit Δ stays short. Two timescales:


- **commit width** ~3–8 s (tight, repeating)  
- **between-object stride** ~18 s then ~30 s then ~50 s (widening)


That is a path on a graph of seven nodes, not seven independent accidents in one hour. Still not a probability. No baseline of “how often this profile opens Docs and how often those Docs get empty revisions” is in the packet. Do not invent one.


**Envelope:** first visit 19:50:19.665 → last empty 19:54:28.674 = **249.009 s** walk+commit. Empties only: **245.622 s**.

## 3. Quotient: what the join is allowed to say


Allowed:


> Local Windows Chrome Default visited these seven exact object IDs in this order immediately before each object’s later-empty revision, with visit→empty gaps 3.005–7.770 s.


Not allowed from this table:


- who held the keyboard  
- extension vs human vs debugger vs native messaging  
- OpenAI process on 7 Sep 19:50  
- Mac session wrote the revision  
- “random chance is 10⁻ⁿ”


Chrome History proves **navigation occurred here**. Drive revisions prove **content became empty**. The join is **identity + order + seconds**. Controller is a third register.

## 5. Pattern language (without fake odds)


Useful pattern words:


- **Carrier:** Default Chrome History + Drive revision API. Finite: seven IDs.  
- **Pair checker:** visit row ↔ empty revision, same ID, Δ ∈ [3.005, 7.770]. Seven pairs hold.  
- **Path:** visit order = empty order.  
- **Bimodality:** commit Δ short vs long; stride widening after door 3.  
- **Defect on door 7:** revision jump 8→18 vs +1 elsewhere.  
- **Holdout:** 8 Sep eighth object; five empty-on-empty Docs.  
- **Non-join:** 23:41 AppX, 00:30 CUA JSON, Norton, WD, OneDrive jsonl — no object ID.


That is the same discipline as the geometry notes: registers stay typed apart; a residual is named (controller); you do not fill it with a nearby process.

## 6. What would close the controller residual


One receipt that names **an object ID and an actor** in the same second:


1. Chrome **debugger / DevTools** attach in 19:50–19:54 (chrome://inspect, `chrome.debugger`, crash dumps, extension debugger events).  
2. Extension **nativeMessaging** or service-worker log for `hehggadaopoacecdllhhajmbjkdcmajg` in that window.  
3. Windows **4688 / Prefetch last-run / Amcache** for Chrome, Codex, ChatGPT **in 19:50–19:55 on 7 Sep** (the 25 Sep prefetch set is the wrong day).  
4. Google **revision modifying-user / session / device** for one of the seven empty revisions.  
5. Any row: object ID → PID or extension instance → edit.


Until then the public sentence stays the table. Surround stays surround.

Qualifications governing §§2, 5, 6 and the frozen geometry wording
The earlier table reports seven exact object-ID matches, matching recorded order and visit-to-empty-revision gaps of 3.005–7.770 seconds. Preserve that object association and the distinct 8→18 revision jump. This amendment reviews the text and arithmetic interpretation; it has not independently re-extracted the Chrome database or Drive revision artifacts.
Timing does not locate the writer. The difference is between two recorded timestamps, subject to their semantics and clock uncertainty. It does not by itself show that navigation caused the edit, that the writer belonged to that Chrome session, or when the writing action began. The earlier sentence that “whatever wrote” was already in that session is not warranted by the table and is superseded by this qualification.
Describe the sample without a distribution claim. The seven selected intervals contain five values from about 3–4.2 seconds and two around 7–8 seconds. This is a descriptive grouping, not an established bimodal population or statistical outlier test. “Not seven independent accidents” likewise exceeds the available baseline: neither independence nor dependence has been statistically established here. The source’s acknowledgement that no chance probability is available remains operative.
Use mathematical terms only with their objects. The 8→18 jump is a revision-index gap; it does not by itself define a quotient or prove a defect. Nearby telemetry forms a set of separately sourced associations; calling it a cocycle requires a declared domain, composition rule and verified identity. “Surround” is useful prose, not a proved algebraic relation.
Actor attribution needs an action binding. A receipt must bind the particular object and writing action or revision to the actor/process claimed, with relevant time uncertainty, authentication and coverage. A process launch, debugger attachment, installed capability or actor/object co-occurrence in the same second alone does not necessarily identify the writer. Such records may narrow candidates while leaving controller attribution unresolved. This qualification replaces the earlier implication that any one of the §6 examples would automatically close that residual.
The seven-door case is a useful worked example of typed joins: browser navigation, object revision, account/session and actor/action evidence remain distinct. Unknown controller does not erase the reported object association, and a strong association does not authenticate a controller.
