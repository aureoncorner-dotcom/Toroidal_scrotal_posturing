FOUR-SPACE EVIDENCE GEOMETRY — CANONICAL PATCH
1. Transport observation space (\mathcal T)
Represent each monitor observation as
[
e=
(r,t_{\mathrm{obs}},p,b,\ell,\rho,\phi,c,E)
]
where:
* (r) = capture / monitor run,
* (t_{\mathrm{obs}}) = observation timestamp,
* (p=(\text{process},\text{PID})),
* (b) = process-creation witness when available,
* (\ell) = local endpoint,
* (\rho) = remote endpoint,
* (c) = current classification,
* (E) = retained classification evidence,
* and
[
\phi\in{S,F,U}
]
with
[
S=\text{Already open at startup},
]
[
F=\text{First observed},
]
[
U=\text{Updated identification}.
]
Define the transport tuple key
[
k(e)=(p,\ell,\rho).
]
A classification update can satisfy
[
k(e_S)=k(e_U)
]
while
[
c(e_S)\neq c(e_U).
]
Therefore the monitor must retain separate state coordinates:
[
M=
(M_{\mathrm{connections}},
M_{\mathrm{classification}}).
]
A change in classification state is not itself evidence of a new connection.
A monitor restart changes (r). If an identical tuple key is observed in separate runs,
[
k(e_{r_1})=k(e_{r_2}),
]
the record establishes repeated observation of that key. It does not, by itself, prove uninterrupted socket or process lifetime.
Cadence as a transport relation
Cadence remains an analysis inside (\mathcal T), not a separate evidence space.
Define a candidate cadence selection:
\left{
e\in\mathcal T:
p(e)=p_{\mathrm{Chrome}},
;
\min_{n\in\mathbb Z}
|t(e)-(t_0+n\tau)|
\le\varepsilon
\right}.
]
For the verified Chrome sequence,
[
\tau\approx600\text{ s}.
]
The measured remote-TCP gaps are
[
600.563,\quad600.180,\quad600.163\text{ s}.
]
Observations near later nominal positions may be retained as cadence candidates while preserving their different event types and endpoints.
Temporal proximity alone does not establish that DNS-side and remote-TCP observations are manifestations of one application request or operation.
Accordingly, this is a candidate cadence group, not an equivalence class unless an explicit equivalence relation is separately defined.
Cross-process association
For temporally adjacent observations sharing a remote endpoint, define an association witness
(r,p_1,p_2,\rho,t_1,t_2).
]
For example, a Chrome observation followed by Codex observations to the same (\rho) establishes:
[
e_{\mathrm{Chrome}}
\prec_{\mathrm{observed}}
e_{\mathrm{Codex}}.
]
This establishes ordering and endpoint overlap.
It does not establish:
[
\text{same request},
]
[
\text{same session},
]
or
[
\text{causal direction}.
]
Use association, not coupling, unless an additional dependency witness is recovered.

2. Application/request space (\mathcal R)
Represent an application request witness as
[
w_R=
(
\text{capture},
\text{initiator},
\text{URL},
\text{method},
\text{request ID},
\text{stream/socket references},
\ell,\rho,
\text{status},
t
).
]
The browser NetLog demonstrates that explicit dependencies can exist among:
[
\text{request}
\rightarrow
\text{resolver/stream job}
\rightarrow
\text{socket}
\rightarrow
\text{HTTP session}
\rightarrow
\text{response}.
]
Those dependency records are stronger than endpoint coincidence.
However, transport-monitor records are not simply a field projection of (w_R). The monitor adds information not contained in that request witness, including:
* operating-system process attribution,
* monitor-run identity,
* polling/observation time,
* monitor connection state,
* DNS-derived classifier state.
Therefore do not write
[
\pi_T(w_R)=e
]
as though the monitor record were generated by deleting fields from a request record.
Instead introduce execution history (h) and observer state (m):
[
O_R(h)=\text{application/request observation},
]
[
O_T(h,m)=\text{transport-monitor observation}.
]
The two observers can expose different properties of the same broader execution history.
The defensible information-limit claim is:
[
\boxed{
\text{Transport observations alone do not uniquely identify application requests.}
}
]
More formally, if distinct admissible request histories can produce the same transport observation,
[
O_T(h_1,m)=O_T(h_2,m)
]
while
[
w_R(h_1)\neq w_R(h_2),
]
then no function of that retained transport observation alone can recover the request witness.
This is loss under observation, not evidence that a particular hidden request has already been identified.

3. Recorded session-metadata space (\mathcal S)
Represent recorded session state as
[
s_i=
(
\text{source},
\text{node},
t_i,
tc_i,
voice_i,
model_i
).
]
Define the model-label projection
[
\pi_M(s)=model.
]
The archived evidence contains observed transitions satisfying
[
(tc_i,voice_i)
\neq
(tc_{i+1},voice_{i+1})
]
while
[
model_i=model_{i+1}=\texttt{bidi}.
]
This produces a genuine collision under (\pi_M).
For a witness (W), define
{
(x,y):
\pi(x)=\pi(y)
\land
W(x)\neq W(y)
}.
]
Let
[
W_{\mathrm{IDs}}(s)=(tc,voice).
]
Then the archived session boundaries supply actual witnesses such that
[
N_{W_{\mathrm{IDs}}}(\pi_M)\neq\varnothing.
]
Therefore
[
\nexists f
\quad\text{such that}\quad
W_{\mathrm{IDs}}=f\circ\pi_M.
]
In plain language:
[
\boxed{
\text{The exposed model label cannot recover the recorded session identifiers.}
}
]
This is the strongest currently demonstrated non-descent result in the four-space architecture.
It establishes a distinction in recorded metadata.
It does not establish:
* engine replacement,
* backend routing,
* reconnect cause,
* context rollover,
* or why the identifiers changed.

5. Observer-State Separation Principle
The transport evidence supports a general distinction between source state and observer state.
Let
[
O(x,\sigma)
]
be an observation of source state (x) under observer state (\sigma).
Then
[
O(x,\sigma_1)
\neq
O(x,\sigma_2)
]
does not by itself imply that (x) changed.
The monitor supplies a concrete case:
[
\text{same tuple key}
+
\text{changed classifier state}
]
without an additional observed connection event.
Conversely, equality of a coarse retained observation need not imply equality of richer source state, as demonstrated by the session/model collision.
Thus:
[
\boxed{
\text{changed observation}\not\Rightarrow\text{changed source}
}
]
and
[
\boxed{
\text{same coarse observation}\not\Rightarrow\text{same richer source state}.
}
]

Define instead a provenance relation
[

\subseteq

\times

Each edge in (J) requires its own evidence:
[

]
[
\text{request}\leftrightarrow\text{session},
]
[

Every proposed link should retain:
* identifier namespace,
* capture source,
* timestamps and clock basis,
* relationship semantics,

A shared identifier or endpoint may support association.
It does not automatically establish causation.
The cardinality of (J) must also be measured rather than assumed:
[
1:1,\quad1,\quad n:1,\quad n
]
are all possible until the actual bindings are recovered.

Corpus integration — 28 September 2026
Readable current definitions and scope
The four collections are R = application/request records; T = transport observations; S = recorded session metadata; D = returned conversation records. These definitions also supply a readable replacement for incomplete or escaped mathematical displays in the earlier text. They name evidence domains, not internal engine stages.
Use V=R⊔T⊔S⊔D with typed, possibly partial and many-to-many relations J_AB⊆A×B. Retain the source artifact, version, field/row locator, identifier namespace, capture, clock basis and uncertainty for every edge. A compatible full bundle is a natural join of those supported relations under the declared matching rules; pairwise temporal proximity alone is insufficient. Even nonempty pair relations need not have a nonempty joint assignment: a=b, b=c and a≠c illustrate that purely logical obstruction.
Represent an observation as O(h,m), with execution history h and observer state m. Observer state includes capture configuration, classifier knowledge, coverage and transform version. Separate first-observed, already-open-at-startup, and identification-update events. Keep process generation and capture run in a local identity key when known; use an explicit relation for cross-capture matching. Repeated endpoint tuples do not prove uninterrupted process or socket lifetime. Event, observation and retrieval time are distinct coordinates.
The retained-artifact audit established narrow observations on its saved domain: 43 paired tc_session_id/voice_session_id changes while model_slug stayed bidi; and 140 distinct returned turn IDs including 102 repeated 1,406-character texts and a four-copy returned record. These support label/identifier and text/record non-descent examples. They do not identify engines, native speech fragments, reconnects, or hidden routes. The separate 516-turn call timing source is a different cohort.
The seven-door browser/revision case introduces separately typed browser-visit and object-revision records. Matching exact object IDs plus recorded order and time is a supported relation in that source report; controller attribution is an additional missing relation. Do not force those registers into an invented backend stage. Statistical bimodality, actor attribution and a cocycle law are not supplied by the seven timestamps.
