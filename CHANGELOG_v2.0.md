# Changes in v2.0

6 September 2026 · Consolidation and reference implementation

## Added

- A concise eight-section core, with the complete v1.6 mathematics retained as the technical baseline.
- A Python reference engine with exact arithmetic in \(\mathbb Q(\sqrt5)\), rational configuration values, half-open endpoint handling, five example configurations and machine-readable outputs.
- A numerical conjugate-coordinate trajectory and a second-order approximation, each kept separate from exact label computation.
- An exact rational upper bound \(\widehat E_\epsilon=|\epsilon|^3[1+(1+|\epsilon|)^2]/3\) for certificate comparisons. The sharper bound remains in the baseline and is displayed numerically.
- Explicit distinction between ideal real-arithmetic certificates and floating execution; an initial boundary fixture records a numerical neighboring-bin outcome without changing the reference label.
- An offline explorer for supplied or newly generated run data, plus a portable verification entry point and release checksums.

## Integrated

- Field Theory Update v0.3: conserved-current winding domain, finite-source modular cut flux, ensemble character identities, fixed-reference loop terminology, path-lift conditions, sampling clocks, closure status and separate scale-gate fields.
- Simulation Protocol v0.5: executable phase-lane contract, complete departure alignment, error and export semantics, and prospective field-lane requirements.
- A technical crosswalk and evidence ledger distinguishing derivations, retained proofs, exact checks, numerical fixtures, conditional references and unresolved physical claims.

## Preserved

- The v1.6 document, source review and complete verification archive, including all nested earlier packages and source snapshots.
- Existing mathematical counterexamples and corrections, with their original domain and kernel qualifications.
- Historical experiment outcomes, missing-data boundaries and unactivated execution records. None is retroactively reclassified by this release.

## Outstanding scientific work

The project still needs a declared field production kernel with a justified stopping rule, its validation data, realized mixing and admissible scale evidence before any Q2 verdict. The two-clock experiment still needs concrete clock/reset inputs and a prospective holdout. A physical application of the density or central-extension calculus needs an explicit model and representation. Those requirements are listed in the updated documents; this reference release does not claim to complete them.
